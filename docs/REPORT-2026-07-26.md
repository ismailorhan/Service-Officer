# Standardisation, performance and UI — 2026-07-26

Seven commits. Everything below was measured before and after, and every change
except one was verified pixel-identical across 36 screenshots in both themes. The
exception is called out as such, because it is the only thing that looks
different in the morning.

Build **2.0.0.11** is in `dist\`, with the new modules confirmed present in its
PYZ rather than assumed.

---

## 1. The standardisation audit, phases 2 and 4

Phase 5 was left alone, as agreed.

**Phase 2 — the stylesheet owns every colour.** 27 per-widget `setStyleSheet`
calls carried palette values, so a theme change meant walking the widget tree
repainting things, and each new colour had to be remembered twice. They are roles
and properties now (`role="hint"`, `kind="destructive"`, `chip="true"`), and
`MainPanel.restyle()` no longer hunts for FlatEdits. Three inline sheets remain,
all geometry: padding and a hover underline that QSS cannot do to a QLabel
without real pointer tracking.

**Phase 4 — one page per file.** `ui/panel.py` was 2,415 lines holding the window
and all eight pages. It is 245 now; the pages are `ui/pages/*`. Later the same
day, `services.py` (932 lines) split into the list (283) and the service detail
(669). All moves were AST-verified against the previous commit — 18 definitions,
then 2, all identical — and each module's imports derived from the names it
actually uses rather than copied.

**What proving it taught, twice over:**

- Deleting an inline `color: FG3` from the fold chevron would have silently
  darkened it to `FG`. Moving a colour to the sheet means *adding a rule*, not
  removing a line.
- The comparison harness lied at first. It grabs windows shown on the real
  screen, so a mouse resting on a row put it in `:hover` and baked `BG_HOVER`
  into the baseline: a 17,461-pixel "regression" that was my pointer. Moving the
  window away is not enough either — Qt clears `WA_UnderMouse` only when a leave
  event arrives, so a stale hover survived the move and cost another 14,699.
  The harness now moves each window to the corner farthest from the pointer and
  delivers the leave itself.

## 2. Performance

Measured on a 2,802 KB history (20,000 rows), medians of repeated runs.

| Path | Before | After |
|---|---:|---:|
| `history.query(limit=200)` | 54.1 ms | **0.6 ms** |
| `history.query(service=…)` | 37.7 ms | **3.4 ms** |
| `HistoryPage.reload()` | 114.3 ms | **59.6 ms** |
| Function calls to open the panel | 979,904 | **54,579** |

Three symptoms, one mistake: paying for the whole file to show the newest page of
it.

- `read()` parsed every line ever written, reversed the list, then took the first
  500. History is append-only and chronological, so `newest_first()` now walks
  the file backwards in 64 KB chunks and stops when the caller has enough. The
  `limit=100000` that meant "everything" is gone.
- The panel filled the History table during construction while opening on the
  Dashboard. It loads when the page is first shown.
- `runs()` had no cheap way to skip a state change, so a machine with **no
  stacks** parsed its entire history to find nothing. A line without `"run"` in
  its bytes cannot be a run, so it is skipped unparsed. The prefilter can only
  save work, and there is a test proving a state row that happens to contain the
  word is still handled by the same check as before.

What the rest of the time is, for the next person who profiles this:
`DashboardPage.__init__` (~0.2 s of a profiled 0.64 s) is Qt building 20 rows of
real widgets, and the panel opens on the Dashboard, so deferring it would not help
what the user waits for. `control.address_of` appears in profiles but runs on a
worker thread and caches — that lesson was already learned and applied.

Not worth doing yet: the flyout costs ~2.5 ms per row (43 ms at 4 services,
130 ms at 50). It only matters above ~30 services, which no install has.

## 3. UI

### The one visible change

The History page's filters were **ten controls in one row needing 1,044 px**,
which set the *whole window's* minimum width to 1,286 — wider than a 1280 screen,
on a tool used over RDP to customer servers. The window opened at 980 and Qt
silently overruled it.

Two rows now, split by the question each answers: which rows to show (service,
range, trigger, clear) and then how much of each plus what to do with them (full
detail, Windows event log, Refresh, Export). **Window minimum: 1286 → 868 px**,
so it now fits a 1024-wide session.

If the two-row look is unwelcome, the alternatives are a narrower service combo
(currently 200 px minimum) or a wrapping flow layout, which Qt has no built-in
for. Say which and it changes in ten minutes.

### Duplication removed

The tray flyout and the dashboard showed the same list with the same eight
methods written twice — which rows are ticked, what the header checkbox shows, a
hidden row not counting as selected, acting on a selection, building the category
groups and the STACKS section — plus the same search box, column header and bulk
bar, including two identical strings. 224 lines out of the two windows, 175 into
`ui/servicelist.py`.

This was not tidiness. `selected()` once asked `isVisible()` instead of
`isHidden()` and came back empty whenever the window had not been shown yet; that
was fixed in the flyout, and the dashboard happened to hold the working version.
The next such fix would have been the same coin toss. The one real difference
stays a difference: the flyout is only as tall as its rows, so it resizes when
they change, while the dashboard is sized by the user — that is one hook.

Eleven glyphs (`›`, `✕`, `▸`, `▲`, `▼`, `↻`, `▤`) were typed as literals while
`theme.py` held constants for exactly that. All eleven name a token now.

### What the audit still reports

- **No** colours outside `theme.py`. **No** glyphs typed inline.
- 19 `setContentsMargins` written as numbers. Most are genuinely one-off (the
  hover card's `13,10,13,11`); inventing fifteen tokens to hide them would be
  ceremony rather than clarity, so they stay visible as exceptions.
- Longest remaining definitions: `theme.sheet()` at 234 lines (it is one
  stylesheet, and splitting it would scatter the thing whose value is being in
  one place) and two `__init__`s of ~140 lines that build a page of controls.

### Still open, needing a decision rather than an afternoon

1. **Phase 5**, deferred: the sentence-style settings ("Try up to 3 times,
   waiting 10 seconds first…") versus labelled fields. It is the one change here
   that alters what people read, so it is a product call.
2. **Two places to act on services** — flyout and dashboard — is deliberate, and
   worth re-confirming now that both are the same code.
