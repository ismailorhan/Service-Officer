## What was done

### 1. A core that doesn't know about the UI
New `core/` package, no toolkit imports anywhere in it:

| Module | Job |
|---|---|
| `config.py` | typed model (dataclasses), v1 file tolerance, defaults merge, atomic save |
| `state.py` | status map **plus the event bus** — the piece the old design lacked |
| `scm.py` | SCM push notifications, now carrying exit code and pid |
| `control.py` | query/start/stop/restart/enumerate, every call remote-capable |
| `history.py` | append / read / trim / CSV export |
| `watchdog.py` | recovery rules |
| `stacks.py` | ordered runner |
| `applog.py` | rotating log at `%APPDATA%\ServiceOfficer\service-officer.log` |

The event bus matters: previously the SCM handler poked the spinner, the icon and
the flyout by hand, and each new feature would have added another call. Now the
tray, the flyout, the hover card, the watchdog and history all subscribe to one
stream.

### 2. The interface is Qt; the tkinter one is deleted
`ui/` with `theme.py`, `icons.py`, `flyout.py`, `hover.py`, `settings.py`,
`tray.py`, and `app.py` as wiring only. Removed: `service_officer.py`,
`panel.py`, `hover.py`, `settings_dialog.py`, `scm_notify.py`,
`service_control.py`, `config.py` (all superseded; git history keeps them).

Everything we fought last night is gone with the toolkit:

| Was | Now |
|---|---|
| Patched Win32 tray message handler over pystray | `QSystemTrayIcon` |
| Hand-drawn scrollbar (the native one ignored its colours) | stylesheet |
| Hand-built queue to marshal onto the UI thread | Qt signals |
| `ShowWindow(SW_SHOWNOACTIVATE)` so the hover card wouldn't steal focus | `WA_ShowWithoutActivating` |
| Foreground polling to know when to close the flyout | `WindowDeactivate` event |
| Twelve pre-rendered spinner PNGs | one `QPainter` transform |
| Settings in a separate process (tkinter needed its own main thread) | a window in the same process |
| Banning astral emoji to avoid ~600 ms of font fallback | still banned — that one is Windows, not tkinter |

### 3. The three features
- **Watchdog** — per-service *keep running*, attempt cap, first delay, backoff
  multiplier, flap guard. It distinguishes a crash (non-zero exit code) from a
  deliberate stop, and never undoes a stop we issued ourselves.
- **Stacks** — ordered start/stop/restart; stop walks the order backwards; each
  step waits either until Running (with a timeout) or a fixed number of seconds.
  Reachable from the tray menu and from a **Test run** button in Settings.
- **History** — every change with its cause, filterable, CSV export, retention
  trim on startup.

### 4. Settings, redesigned as agreed
Follows `docs/settings-mockup.html`: sidebar sections, list→detail navigation
instead of nested split panes, and recovery expressed as sentences — *"Try up to
`3` times, waiting `10` seconds first and multiplying that wait by `2` each
time."*

### 5. Housekeeping
- **46 tests in the repo**, run by `pytest`; `build.bat` and the release
  workflow now run them and refuse to build if they fail.
- Release workflow updated for the new one-dir Qt build (it would otherwise have
  produced a broken release from the old one-file command).

## Assumptions I made

1. **PySide6** rather than PyQt6 — LGPL, so a commercial product stays simple.
2. **Settings runs in-process.** The plan had it staying a separate process, but
   that boundary only existed to keep tkinter's main-thread requirement happy.
3. **Recovery is off by default** for every service, including ones you already
   had configured. Upgrading should not silently start restarting things; you
   turn it on per service.
4. Defaults when you do turn it on: 3 attempts, 10 s first wait, ×2 backoff, give
   up after 5 stops in 30 minutes, clean stops left alone.
5. **A crash means a non-zero exit code.** That's how a stop from services.msc is
   left alone. Some services exit 0 when they die — for those, tick *"Also
   restart after a clean stop"*.
6. **Notifications** use the tray balloon (`showMessage`) — Windows renders it as
   a toast, and it needs no extra dependency.
7. **One-dir build, pruned.** PyInstaller emitted 101 MB; dropping the software
   OpenGL fallback and Qt's TLS libraries brings it to 65 MB, and I launched the
   pruned build to confirm it still runs. Installer compresses to 19.4 MB.
8. **Test run** in the stack editor performs a real start, not a dry run.
9. Version **2.0.0** (new UI stack, new config version).
10. The `machine` field exists throughout config and control, but there is **no
    remote-machine UI yet** — that's roadmap #4, groundwork only.

## What I could not verify, and what to check first

Verified: 46 automated tests, the app launches and logs your four services, the
built exe runs (before and after pruning), the installer compiles.

Not verified — needs a UAC prompt or a human at the tray:

1. **Live crash recovery.** Kill a service's process (Task Manager → End task) and
   confirm the toast, the restart, and the history line. This is the single most
   important thing to try.
2. **A real stack run** — order, timeouts, and that a stack stop isn't undone by
   recovery (covered by a test, but not against real services).
3. **Tray behaviour on your setup** — click to open, hover card, and the flyout's
   position on the RDP/multi-monitor screens.
4. **Installing over 1.1.0.** The old install was a single exe, the new one is a
   folder; files from 1.1.0 will be left behind in `C:\Program Files\Service
   Officer` (harmless, but a clean uninstall first is tidier).

## Known rough edges

- `QSystemTrayIcon.geometry()` returns an empty rect while the icon sits in the
  overflow ("^") area; the flyout and hover card then fall back to the cursor
  position instead of anchoring to the icon.
- Hover uses a 250 ms cursor-vs-icon poll, because Qt exposes no hover signal for
  a tray icon.
- The stack **Test run** shows progress in the flyout's status chips rather than
  in the Settings window itself; a proper progress list belongs in the stack
  editor.
- No code signing yet, so SmartScreen will still warn on other machines.
